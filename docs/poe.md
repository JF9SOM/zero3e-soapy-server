# PoE 運用の検討 — 2026-11-26

## 状況
- Radxa ZERO 3E PoE HAT（IEEE 802.3af 対応とされる）は購入済み。PoE 給電機器（PSE）は **未所有** → 購入が必要
- 現状は USB-C 5V/3A 電源（OTG ポート）。PoE と USB-C の同時接続はしない（逆流などの危険回避。実験では未確認）

## Radxa 公式ドキュメント（https://docs.radxa.com/en/zero/zero3/accessories/3e-poe-hat）で確認できたこと
- PoE 機能は銅ピラーとネジで HAT と基板を接続して実現。**固定しないと PoE が使えない**
- 相手側のスイッチ/ルーターが PoE 対応であること
- イーサネットのピン 1,2,3,6 が給電とデータの両方、4,5,7,8 はデータのみ（= 給電はデータ対 [802.3 の Alternative A / Mode A] で受ける。スペアペア [4,5,7,8] 給電のみの PSE では給電されない可能性があり、**要確認**）
- HAT のネジ端子は「12V DC Output」であり **5V 出力ではない**（周辺機器をつながない）
- HAT の 5V 出力電流の定格は、この文書・検索では見つからず **未確認**

## 買うもの（案）
- IEEE 802.3af（at/bt 対応でも可）の **PoE スイッチ**（ギガビット、アンマネージドで可。PoE ポートの総給電に余裕があるもの）
  - Mac は同じスイッチの別ポートへ。固定 IP（192.168.50.x）のまま使える
  - スイッチ PSE は一般に Alternative A で給電する（個別製品の仕様で要確認）
- 1 ポート PoE インジェクタを選ぶ場合: **ギガビット対応**かつ **Mode A（データ対に給電）または 4 ペア給電**の仕様を確認（Mode B のみのインジェクタは、この HAT では給電されない可能性があり、要確認）
- パッシブ PoE（24V 等の簡易型）は避ける。802.3af 準拠のみ

## 電力の見積もり（実測＋推定）
- 実測: HackRF＋PortaPack 約 0.85〜0.88 A @ 約 4.86 V（約 4.3 W）、LNA のバイアスT 増加約 0.02 A
- ZERO 3E 本体は未測定。5V 側の合計は 6〜7 W 程度の見込みに HAT の変換損失が加わる → 802.3af（PD 側最大 12.95 W）に収まる見込み（未検証）

## 試験計画（機器到着後）
1. 銅ピラー・ネジで HAT を固定。USB-C 電源を外して PoE のみで起動
2. HackRF（USB 電流計経由）で、受信前/受信中（3.2・10・16 Msps）の電流・電圧を測る。5V が落ちないか（4.75 V を下回らないか）を確認
3. バイアスT オン/オフ、LNA、20 分程度の連続受信、温度（`journalctl -t zero3e-temp`）

## 追記（2026-11-26）: ピンの懸念の訂正と、パッシブ PoE を使う場合の条件
- IEEE 802.3af/at ではピン（Alternative A: 1/2・3/6、Alternative B: 4/5・7/8）が標準化されており、**PSE はどちらか一方、PD は両方を受ける**決まり。規格準拠どうしなら商品案内にピンの記載がなくても組み合わせ可能。
  上の「Mode B のみだと給電されない可能性」は、Radxa 文書の記述（1,2,3,6 の説明）に基づく HAT 側の懸念で、HAT が Mode B を受けるかは未確認（届いてから確認）
- ユーザー判断: アクティブ品は高価なため、**パッシブ PoE も候補**。PoE の件はユーザーが追って調べる（未実施）
- パッシブを使う場合の条件（Claude の整理。実機での検証はしていない）:
  1. 電圧は 48V 前後（目安 48〜54V、57V 未満）。12V/24V では起動しないか不安定、57V 超は破損の恐れ。HAT 自体の入力定格は未確認
  2. 48V 0.5A（24W）以上の安定化電源（ZERO 3E＋HackRF は約 6〜7W の見込み）
  3. 本物のギガビット対応（100Mbps 止まりの安価品に注意）。`ethtool` と `iperf3` で実測（20 Msps の CS8 で約 320 Mbps）
  4. 給電ピン・極性は HAT が受けられること（パッシブは多くが Mode B 固定。HAT が受けなければ給電されないだけで、破損の可能性は低いと考える）
  5. 安全: 電源投入と同時に出力ポートに 48V が出続けるため、**Mac の LAN など PoE 非対応機器を出力側（POE OUT）につなぎ禁止**。ポートにラベル。USB-C 電源と PoE の同時接続は禁止
  6. 手順: 届いたらテスターで出力ポートの電圧・ピン・極性を確認 → 短い Cat5e で HAT に接続（USB-C 電源は外す）→ 起動確認 → 電流・電圧・リンク速度・iperf3 を測定。起動しなければ即切り離して返品

## 試験結果（2026-11-27）: PoE インジェクター（Premiertek PT-POE-G4850W）＋ Radxa PoE HAT
構成: Mac(AX88179A) → インジェクター DATA → インジェクター POWER+DATA → ZERO 3E（PoE HAT、USB-C 電源は外して PoE のみ）、HackRF＋PortaPack 接続。

確認済み:
- **PoE のみで起動**（`uptime` で起動直後を確認）。SSH 可、`end1` は 1000 Mbps / full。HackRF One を `lsusb` で認識、`soapyremote-server` は稼働。
- 電源まわりの異常ログ（低電圧・USB 過電流・USB リセットの繰り返し）なし。起動時の `aicbsp`（Bluetooth）失敗は PoE 以前の起動にもあり、電源とは無関係。
- 電流計（HackRF 側）: 電圧 **4.88 V**（USB-C 時は約 4.86 V）。電流は初め約 0.67 A。
- FBSAT59 から HackRF に接続して**受信できた。バイアスT も動作した**（ユーザー確認）。受信中の CPU 温度 約 40.6°C、SoapySDRServer の CPU 約 8 %（確認時点）。

分かったこと:
- 0.67 A は、`dmesg` の USB ID から、**PortaPack が Mayhem モード（1d50:6018）で起動した状態**だった可能性が高い（その後 HackRF モード 1d50:6089 に切替わり再接続。ログ上の事実）。0.67 A を測った時点のモードは未確認。
- 「FAIL: SoapyRPCUnpacker::recv(header)」は、クライアント切断時のログと見られる（未確認）。

未確認:
- インジェクターがアクティブ式かパッシブ式か（起動した事実のみ。出力電圧・ピンは未測定）
- 受信中の電流値（数値の記録なし）、長時間（20 分以上）の連続受信、高レート（10 Msps 超）での 5V 余裕
- 「PoE なしの LAN ケーブル＋USB-C 電源」での併用可否・逆流防止（引き続き未確認。PoE と USB-C の同時接続は禁止のまま）

## 試験結果（2026-11-27）: PoE HAT を付けたまま USB-C 電源のみで使う（PoE なし）
構成: 普通の LAN ケーブルで Mac(AX88179A) と ZERO 3E を直結（インジェクターは経由せず）、HAT は付けたまま（銅ポスト・ネジも固定のまま）、USB-C 電源、HackRF＋PortaPack。

確認済み:
- **起動し、SSH 可、`end1` は 1000 Mbps**。電源まわりの異常ログ（過電流・低電圧）なし。
- PortaPack の状態と電流（電流計は HackRF 側）: Mayhem モード（1d50:6018）約 0.62 A → HackRF モード（1d50:6089）に切替後 約 0.54 A → FBSAT59 で受信中（3.2 Msps）**0.70 A、4.92 V**。
  最初の USB-C 試験（HAT なし、0.85〜0.88 A / 約 4.86 V）より低い。理由は未確認（PortaPack の表示状態、測るタイミング等の可能性。確認していない）。
- 受信中の ZERO 3E: 送信量 約 54 Mbps（3.2 Msps の CS8 相当）、CPU 温度 約 42°C、SoapySDRServer CPU 約 8 %。
- HAT の部品の発熱は、ユーザーによる触診の確認結果を聞いていない（未確認）。

結論（この試験の範囲）: **HAT を付けたままでも、USB-C 電源のみで普通に起動し受信できた**。HAT 側への逆流による異常は、ログ上は見られなかった。ただし回路図がないため逆流防止の有無は不明で、長時間の影響（HAT の発熱など）は未確認。PoE と USB-C の同時接続は、引き続き禁止。
未実施: バイアスT のオン、20 分以上の連続受信。
